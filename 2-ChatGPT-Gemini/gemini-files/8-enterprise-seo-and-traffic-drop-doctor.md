## ARTICLE 8-seo-data-api-use-cases

### 8 SEO Data API Use Cases For Agencies and Enterprises

- **Updated**: 2026-10-05

## TL;DR
An SEO data API turns SEO data from a manual, per-report activity into an automation and intelligence layer: automated dashboards, bulk pulls beyond UI limits, workflow automation (redirects, link alerts), sales lead-scoring with authority/traffic/cost metrics, portfolio case studies for pitches, alternative data for investors, competitor scorecards, and forecasting templates.

## Framework / Step-by-step
The 8 use cases:
1. **Automated reporting & dashboards** — warehouse API data + mix with Search Console/analytics; visualize in a BI tool or spreadsheet. Example: referring domains aggregated by author with sparklines; Search Console traffic + followed referring domains from higher-authority sites per post. Report per business unit, product line, custom segment, author.
2. **Pull data at scale** — beyond UI limits (bulk-analysis screens usually cap how many URLs you can check at once; APIs are far more flexible, within your plan's quota): authority scores for thousands of URLs in a spreadsheet, top keyword + position + traffic per URL for content inventories; mix backlink, site audit, keyword research, and rank tracking data.
3. **Automate strategic workflows** — link alerts/triggered actions; redirect discovery pipeline for huge sites (feeds a redirect-matching script); tagging keywords by product/service/location/BU in internal systems; combining SEO + Google Ads data to cut ad costs. (Don't use data pipelines to hunt expired domains for passing ranking signals; that violates spam policies.)
4. **Enrich lead/prospect scoring** — pull domain authority (company size/authority), estimated organic traffic cost (visibility potential), estimated paid traffic cost (current marketing budget) per prospect. Score for growth-gap selling (low organic + high potential) or budget-size selling (high paid spend). Due diligence on companies.
5. **Case studies & B2B sales** — aggregate client portfolio performance into live pitch dashboards (e.g., number of #1 rankings, clients past 1M organic visits, average ad-spend savings). Use only real, verifiable, client-approved figures.
6. **Predict/benchmark market movements** (investors) — alternative data: monitor portfolio digital performance, instant traffic-loss alerts, cross-company pattern detection (simultaneous drops across a vertical = market-wide event). Example (illustrative): catching a 25% organic traffic loss as an early investment warning.
7. **Competitive intelligence** — automated competitor scorecards (notebook or spreadsheet templates: general, MoM, YoY), resource estimation to catch competitors, movement monitoring, historical insights, gap analysis at scale.
8. **Forecast SEO opportunities** — time-series forecasting scripts for future traffic, traffic value, competitor traffic/value, page-level traffic, core-update performance (see the SEO forecasting article).

## Actionable checklist
- [ ] Pick the dataset you pull most often and script it via the API instead of exporting by hand
- [ ] Stand up one automated dashboard: API + Search Console in a BI/dashboard tool
- [ ] Replace large manual authority/keyword bulk lookups with API pulls
- [ ] Build the redirect workflow: 404 + RDs data → redirect matcher script → auto-flag >3 RDs pages
- [ ] Add domain authority / estimated organic cost / estimated paid cost to your CRM as lead-scoring fields
- [ ] Create a portfolio performance dashboard for sales pitches
- [ ] Build a competitor scorecard notebook or spreadsheet (add API key, add domains)
- [ ] Run one forecast template for next year's budget conversation

## Data points & benchmarks
- Bulk-analysis UIs usually cap URLs per pull; APIs scale further (within plan quotas)
- Example sparkline view: followed referring domains from higher-authority sites per post vs Search Console traffic
- Investor example (illustrative): a 25% organic traffic loss spotted via dashboard before it hit valuation
- Ecommerce context: digital performance data is used as an alternative-data signal for investors (a supporting signal, not a sole basis)
- Pitch metrics should be real client results you can document, not round-number marketing claims

## Mistakes to avoid
- Manual reporting when a daily automated pull exists
- Judging prospects on a single metric — combine authority + organic cost + paid cost
- Treating website data as sufficient alone for investment decisions — it's one alternative signal
- Ignoring cross-company patterns — simultaneous drops signal market events, not site issues

## Key principles
- API = operational efficiency + executive insight speed
- Anything you do manually twice should be automated: alerts, redirects, scorecards, forecasts
- SEO data has value beyond SEO: sales qualification, case studies, investment signals
- Validate API data against your own first-party sources (Search Console, analytics); third-party estimates are modeled, not exact

## ARTICLE brand-awareness-dashboard

### How to Build a Brand Awareness Dashboard

- **Updated**: 2026-10-05

## TL;DR
A step-by-step build of a live, auto-updating brand awareness dashboard in any BI/dashboard tool using your SEO tools' data connectors (or scheduled exports): filter everything by a brand-name regex, then track branded traffic/share of voice, top brand pages, all brand keywords with SERP-feature ownership, and the quality/location of branded backlinks. Rationale: brand drives discovery and conversion in search AND AI/LLM visibility.

## Framework / Step-by-step
1. **Connect your data sources** (a connector or scheduled export from each tool into the dashboard tool):
   - Backlink/traffic tool: traffic, keywords, backlinks overview
   - Rank tracking tool: share of voice, SERP features, keyword set positions (segment by device)
   - Site audit tool: technical/indexability/Core Web Vitals
   - Search Console and analytics for first-party branded traffic
2. **Add more fields/dimensions** from each connector as needed.
3. **Make every field filterable**: only combine fields that share a data grain (mixing granularities breaks charts); use input boxes + regex/contains filters for brand name + variants/misspellings (e.g., `acme|acmee|acm3`); build the regex from how other sites anchor-text your brand. Make sure the dimensions you filter on are exposed in the data source, or filters will fail silently.
4. **Track most important brand keywords** (rank tracking): brand-only project or tags; scorecards with compact numbers + sparklines; exclude tracked competitors from your own totals.
5. **Track top brand pages** (top pages data): scorecards with month-over-month deltas + page-level tables.
6. **Monitor ALL brand keywords** (organic keywords data): scorecards (traffic, CPC, position, volume); pie chart of SERP feature ownership (exclude rows with no feature); keyword table (volume, difficulty, position, traffic, growth).
7. **Monitor brand backlinks**: totals, new vs. lost, net gain; pie charts by authority bucket and by link location (in-content vs other); link language bars (region proxy); detail tables for referring domains, anchors, and links sorted by traffic.

## Actionable checklist
- [ ] Connect backlink, rank tracking, and Search Console data to your dashboard tool
- [ ] Build a brand regex from anchor-text variants and misspellings; wire it into input-box filters
- [ ] Confirm each data source exposes the dimensions you filter on
- [ ] Add brand keyword scorecards with sparklines; exclude competitors from your own totals
- [ ] Add top-pages scorecards (traffic + traffic value deltas) and page tables
- [ ] Add all-brand-keywords view + SERP feature ownership pie
- [ ] Add backlinks section: new/lost/net gain, authority distribution, in-content share, languages, anchor tables
- [ ] Record monthly benchmark: % of branded backlinks from high-authority domains (e.g., 60+ on your tool's scale)
- [ ] Compare brand-filtered vs unfiltered views to isolate brand's share of total performance
- [ ] Monthly: export a PDF, use an AI assistant to help spot trends (verify any correlation it suggests), share highlights

## Data points & benchmarks
- Example findings from one brand: branded links grew by 228.1K vs 25.4K for non-brand links in a quarter; brand keyword traffic +28% in a quarter
- Monthly KPI to log: percentage of high-authority (60+) branded backlinks
- Authority pie example buckets: 80–100 (1.3%), 60–80 (8.8%), 40–60 (15.4%), 20–40 (22.8%), other (51.3%)
- In-content vs other: 25.3% vs 74.7% (in-content is the meaningful share)

## Mistakes to avoid
- Combining dashboard fields of different granularity — charts break
- Leaving needed dimensions unexposed in the data source — filters silently fail
- Only tracking manually chosen brand keywords — an all-organic-keywords view catches breakout terms
- Judging links without authority/location/language context — quality matters more than count
- No benchmark baseline — you can't measure brand growth without a starting snapshot

## Key principles
- "You can't optimize what you don't measure" — brand visibility now influences search, LLM, and buyer-discussion presence
- Brand is both top-funnel (discovery) and bottom-funnel (conversion)
- Filterability first: every chart must respond to the brand regex, so brand vs non-brand comparison is one click
- How third parties reference your brand (anchors, languages, authority) is a leading indicator of brand health

## ARTICLE enterprise-content-marketing

### Enterprise Content Marketing Strategy To Drive Growth

- **Updated**: 2026-10-05

## TL;DR
Even with domain authority, enterprises must deliberately choose content and put in the work. Start with competitor-proven topics, build a base team (SEO + writer + editor), expand from BOFU to TOFU, and scale through translation, free tools, programmatic pages (only with unique data, never thin templated pages), and video. Progress beats perfection: bootstrap, show wins, climb the maturity model toward centralization.

## Framework / Step-by-step
1. **Pick what to create**: start with competitor top pages (export + combine) or a content-gap export clustered by parent topic. Sequence: BOFU transactional first → informational + video → events/courses/ebooks/white papers/podcasts as resources grow. Don't skip TOFU forever — it widens the pipeline and owns expert positioning.
2. **Produce by creator type**:
   - SEOs writing: interview internal experts; repurpose their papers/talks; mine sales team insights; add to existing knowledge (no copycat content)
   - Writers: run card-sorting exercises (search data + top-page topics on index cards → writers group into outlines); or hand them content briefs; track performance per author (group their URLs in your reporting tool)
   - Experts: empower them to write, or interview them / have them review drafts
3. **Improve existing content**: declining-traffic pages (top pages with traffic declining over 6–12 months), low-hanging fruit (positions 4–15), featured snippet gaps (#1–5 rankings where target doesn't own the snippet).
4. **Scale plays**: translate winners, syndicate, redirect 404s with links, internal links, "vs" pages (avoid feature tables; use user proof + data quality), free tools, programmatic pages from proprietary data (each page needs unique value, or it's scaled content abuse), video structured around search queries.
5. **Build the team**: bootstrap with SEO + writer + editor; add strategists/PMs/designers later; external contractors are often easier than headcount.
6. **Get buy-in and scale**: show revenue (SQLs/MQLs) broken down by author/product/BU; join training initiatives; build BU scorecards; integrate with paid (retargeting) and social (amplification); align with "top 20/top 50" corporate growth projects; climb toward a Center of Excellence.

## Actionable checklist
- [ ] Export 3–5 competitors' top pages; combine into a seed content list
- [ ] Cluster content-gap exports by parent topic (a keyword research tool or your own grouping)
- [ ] Check search intent per keyword to reject intent-mismatched requests (keyword-sprinkling on product pages)
- [ ] Filter top pages for traffic declines over 6–12 months; prioritize refreshes
- [ ] Snippet hunt: keywords where you rank #1–5 but don't own the featured snippet → add concise, direct answers
- [ ] Run one card-sorting workshop with writers per major topic
- [ ] Translate proven content into other company languages; implement hreflang
- [ ] Reclaim links: top pages by links → 404 filter → redirects
- [ ] Fix generic internal anchors ("learn more") using a crawler's anchor-text export
- [ ] Launch one free tool and one programmatic template from proprietary data (unique data per page)
- [ ] Publish on an easy platform (blog) — avoid pages that need custom dev work per post
- [ ] Report wins as revenue by author/product/BU; repeat the "dog and pony show"

## Data points & benchmarks
- One large SaaS blog: ~8.2M organic visits/month ≈ $5.3M+/month in equivalent ad spend (a tool's estimate, older figure)
- Search-driven YouTube case study: 500k+ subscribers from <300 videos; many videos >1M views (one channel, not typical)
- Featured snippet trick: search "term -site.com" to reveal the next-eligible snippet
- Base team = 1 SEO + 1 writer + 1 editor

## Mistakes to avoid
- Copycat content — not future-proof; add new information instead
- Skipping TOFU — narrows pipeline, cedes "expert" status to competitors
- Optimizing product pages for informational intent — intent mismatch
- Requiring custom design/dev for every page — publishing friction kills output
- Waiting for perfect team/funding before starting — bootstrap and show progress

## Key principles
- "Big enterprise websites rank for everything" is a myth — they still have to choose topics and do the work
- Don't let perfect be the enemy of good
- Build momentum one win at a time; replicate success across BUs
- Align content pushes with the company's top 20/top 50 growth priorities

## ARTICLE enterprise-link-building

### Enterprise Link Building & The Power Of Links

- **Updated**: 2026-10-05

## TL;DR
Links still matter (in one practitioner's disavow experiment, removing good links lost rankings and traffic), but at enterprise scale most links happen without SEO — PR, ads, partnerships, events. The SEO's job is to enable those teams with best practices, run the high-ROI plays enterprises uniquely can (reclamation, unlinked mentions, linkable assets, cross-site linking), and get budget by pricing links in dollars.

## Framework / Step-by-step
1. **Clear the organizational hurdles**:
   - Legal often bans employee outreach ("representing the brand") — get creative or offload to vendors
   - Build the budget case with an agreed value per recovered referring domain (e.g., $400, an illustrative internal assumption, not a market price): 250 redirects × 10 RDs × $400 = $800,000 pitch
   - Prioritize pages tied to company priority products (someone's bonus depends on them)
2. **Coordinate, don't control**: PR, social, paid, events, partnerships, influencers, affiliates all earn links. Train them via internal sessions, best-practice docs, weekly calls. "Make many people do a little bit better" beats doing everything yourself.
3. **Run the tactic menu** (start from the link-related quick wins in your site audit or SEO platform):
   - Linkable assets: surveys, studies, tools/calculators, awards, how-tos, coined terms, infographics, thought-leader quotes
   - Consolidate cannibalizing pages into stronger pillar pages (combine + redirect)
   - Promote selectively via other teams (ask for everything → they promote nothing)
   - Unlinked brand mentions (also of key employees, famous quotes, your study stats) → ask for the link
   - Link reclamation: 404s with RDs → 301 redirects (scripted; automate at >3 RDs + >5 hits/month)
   - Copy competitors: top pages by links and site-structure views beat noisy link-intersect comparisons at scale
   - Internal links (use a crawler's link-opportunity and anchor exports; fix generic anchors)
   - Link between company-owned sites where relevant (gray area: keep it natural, since large-scale cross-linking just to pass ranking signals can be treated as a link scheme)
   - M&A: acquired businesses bring content + links to consolidate (buying expired domains purely for ranking signals violates spam policies)

## Actionable checklist
- [ ] Check what outreach legal/compliance actually allows before planning tactics
- [ ] Price your reclamation project: top pages by links → 404 filter → RDs × your agreed value per RD
- [ ] Audit competitors' top pages by links / site structure for replicable link-magnet plays (tools, studies, glossaries, academies)
- [ ] Set up brand-mention alerts in a content research tool, filtered to unlinked domains
- [ ] Consolidate cannibalizing pages: merge + 301
- [ ] Fix generic internal anchors using a crawler's anchor-text export
- [ ] Create one linkable asset (study or free tool) per quarter
- [ ] Run one training/best-practices session for PR/social/paid teams
- [ ] If outreach is allowed: email-finder + outreach-management tools for scaled personalized outreach (tag any paid placement rel="sponsored" or nofollow)

## Data points & benchmarks
- One disavow experiment: removing good links caused ranking AND traffic losses on affected pages — evidence that links influence rankings, not just correlate
- ~2/3 of links on the web disappeared over 9 years (older link rot study) — reclamation is an ongoing source of value
- $400 = illustrative value per referring domain used to price projects; example pitch $800K (250 × 10 × $400)
- Google has described links/PageRank as a long-standing signal for assessing authority and trust
- Keep redirects in place for at least a year (indefinitely while the old URL still earns links or traffic) — don't re-redirect old consolidations

## Mistakes to avoid
- Sending employees to do outreach without legal clearance — projects die in legal review
- Asking partner teams to promote everything — selectivity is the price of cooperation
- Relying on link-intersect comparisons on enterprise sites — too noisy; use top pages by links instead
- Abusive cross-linking between owned sites — fine only when links are genuinely relevant
- Over-disavowing: tool-flagged "toxic" links usually shouldn't be disavowed

## Key principles
- The vicious circle of SEO: pages that reach the top attract more links over time — get to the top first
- Enterprise link building = enabling other teams + reclaiming what you already earned
- Money math unlocks budget: links × dollar value beats "best practice" arguments
- Consolidation is link building: merging weak pages concentrates authority

## ARTICLE enterprise-saas-seo

### Unlocking Growth Through Enterprise SaaS SEO

- **Updated**: 2026-10-05

## TL;DR
Enterprise SaaS SEO = attracting people searching for problems your product solves. The highest-ROI approach is product-led content: score every topic for "business potential" (how naturally the product fits), support long sales cycles with content at every stage, then layer enterprise mechanics — translation, free tools, programmatic data pages, reclamation, and money-based reporting. The approach builds on the other enterprise SEO guides in this library, applied to SaaS.

## Framework / Step-by-step
1. **Accept SaaS-specific challenges**: long/complex sales cycles (need per-stage content), stiff competition, organizational complexity, buy-in fights.
2. **Model the winners**: SEO-native SaaS companies (product-led content: every article/video teaches a concept + shows the product solving it), a productivity SaaS (template gallery = use-case landing pages), a large collaboration-software vendor (help-style content aligned to user needs).
3. **Content engine**:
   - Score each planned topic for Business Potential (1–3: how valuable it is to pitch the product in that topic)
   - Find topics from competitors' top pages; cluster content-gap output by parent topic
   - Start BOFU → expand to TOFU informational + video
   - Refresh: declining traffic (6–12 mo), positions 4–15, featured snippet gaps (#1–5 without snippet)
   - Translate winners — a keyword research tool can translate saved keyword lists and show local volume/KD per market
   - "vs" pages (user proof + data quality, not feature tables), free tools, programmatic pages from proprietary data (unique data per page; no thin templated pages), video structured around search queries
4. **Links**: enable PR/social/paid teams; linkable assets; unlinked mentions; reclamation (404 + RDs × an agreed value per RD, e.g., an illustrative $400); consolidate cannibalizing pages; internal links; natural cross-links between owned sites; inherit links via genuine M&A (not expired-domain purchases).
5. **Technical SEO** by priority: HIGH indexing/noindex/canonicals + schema (only for search features); MEDIUM page experience (CWV, HTTPS, mobile, interstitials); LOW broken links/redirect chains/sitemaps; situational hreflang + crawl budget; specialized: JS SEO, migrations, M&A, log files (in most cases Search Console's Crawl Stats report suffices).
6. **Reporting**: equate metrics to money, compare vs competitors, per-audience reports (see the enterprise SEO metrics and reporting article).

## Actionable checklist
- [ ] Add a Business Potential score (1–3) column to every content brief/topic list
- [ ] Build a template/use-case section (template-gallery model) if the product supports it
- [ ] Sequence content: BOFU comparison/alternative pages → informational → video
- [ ] Translate saved keyword lists in a keyword research tool to size international demand before translating content
- [ ] Launch free tools tied to product data as lead-gen
- [ ] Ship one programmatic template (e.g., "[product] for [industry/use case]")
- [ ] Run the standard enterprise plays: 404 reclamation, snippet gaps, internal links
- [ ] Report in revenue/SoTV terms to survive budget reviews

## Data points & benchmarks
- Business Potential scoring: 3 = product is the main way to solve the topic; 1 = barely fits
- In one older study, >6% of sites still redirected HTTPS→HTTP
- Google follows up to 10 redirect hops (worry after 5)
- ~2/3 of links decayed over 9 years (older study); $400/RD is an illustrative reclamation valuation
- YouTube case study: 500k+ subs on <300 videos — one example that search-driven video can work for SaaS

## Mistakes to avoid
- Pure informational content with zero product tie-in (or the reverse: keyword-stuffed product pages)
- Skipping TOFU — competitors become the perceived experts
- Copycat content — add new information so it deserves to exist
- Manual sitemaps and unused schema — automate sitemaps; schema only for search features
- Log file analysis projects when Search Console's Crawl Stats report covers most needs

## Key principles
- Product-led content: teach the problem, show the product solving it — a natural subscription path
- Business Potential score decides what deserves creation, not raw volume
- SaaS sales cycles are long: capture each journey stage or leak pipeline

### What is an Enterprise SEO Audit & How To Do One

- **Updated**: 2026-10-05

## TL;DR

   - General SEO audit (11 steps: crawl → traffic drops → duplicates → indexability → mobile → CWV → broken-page reclamation → sitemap → on-page → declining content → competitor keywords)

   - Internal link analysis (opportunities + broken internal links + orphan pages)
   - Local SEO audit (GBP, NAP, reviews, links, on-page)
4. **Put together deliverables and reports** — agree format up front (deck, doc, spreadsheets, or tickets). Report 5–10 main issues max. Translate each fix into cash.

## Actionable checklist
- [ ] Ask stakeholders the specific reason for the audit before scoping anything
- [ ] Check traffic-drop context first (e.g., if a drop lines up with a Google core or spam update, a technical audit is the wrong starting point)
- [ ] Segment the site via a folder-level (site structure) view before crawling
- [ ] Use crawl sampling instead of full crawls — you don't need weeks of crawling to detect important changes
- [ ] Set up a recurring site audit project to track fix progress
- [ ] Run daily crawls on a custom list of template-representative pages with change alerts — catch issues early
- [ ] Scope deliverables (presentation / doc / sheets / tickets) in writing before starting
- [ ] Limit the report to 5–10 issues; drop everything else
- [ ] Attach a dollar value to every recommended fix

## Data points & benchmarks

## Mistakes to avoid
- Auditing everything "because it's an audit" — expensive, slow, mostly wasted
- SEO checklists at scale — no ROI in checking every little thing on every page
- Trusting tool-flagged "toxic links" and mass-disavowing — questionable methodologies; disavows often hurt
- Ignoring the actual reason the client asked (e.g., running a technical audit when the drop was an algorithmic update)
- Full crawls of enterprise sites when a sample across templates suffices

- "The key to enterprise SEO is doing the basics better than anyone else."
- Most big brands only rank for their branded searches — audits should surface that unbranded opportunity
- Equate fixes to cash: "redirect these 100 pages → recovers 2,500 links, worth roughly $1M at an assumed replacement cost per link" (an internal estimate, not a recommendation to buy links) beats a task list

## Framework / Step-by-step
1. **Identify targets**: an organic-competitors view in your SEO tool (with date comparison for market evolution); if market players are unknown, look up the domains ranking for your market terms and compare their estimated organic share of voice. Check fit with your content strategy — acquiring a property that already ranks in a target market is the fastest way to enter it.
2. **Pre-screen risks**: declining traffic, history of search-update hits (traffic drop diagnosis), forecast future traffic, scan the link profile (good links = asset; paid, PBN, or other manipulative links = risk/liability).
3. **Due diligence & valuation** (during exclusivity): deeper pass on traffic, rankings, backlinks, forecasts + an audit/quick-wins pass to size upside potential. Targets often own multiple domains — check them all.
4. **Merge or not**: trade-off = more SERP listings (keep separate; common for news sites in Google News/affiliate) vs. one stronger listing (merge). Typical 3-stage merge: (1) "an X company" tag → (2) migrate domain under main brand → (3) full rebrand/integration.
5. **Migrate safely**: the two big traffic killers are missing redirects and killed content. Preserve legacy branded-term traffic (people search old names for years). Verify TLS certificates work across domains or users hit errors despite redirects.
6. **Post-acquisition monitoring**: group the old domain + new path in one tracking view; watch for traffic drops; compare organic keywords before/after to localize losses. Crawl the most-linked old URLs (top pages by links → custom URL list in a crawler) and check redirect status codes (301/308 good; 302/307 tell Google the move is temporary). Keep renewing old domains forever so competitors can't grab them.
7. **Train and transfer** best practices to acquired teams.

## Actionable checklist
- [ ] Screen targets: organic competitors + estimated share of voice for market terms
- [ ] Diagnose any traffic declines and update-history hits before valuation
- [ ] Run a quick-wins audit on target domains to quantify upside
- [ ] Decide merge vs. keep with the listings-vs-strength trade-off
- [ ] If merging: map redirects for every linked URL; migrate all content
- [ ] Keep ranking for the acquired brand's name (dedicated page or documentation)
- [ ] Verify TLS/HTTPS across both domains before cutover
- [ ] Set up a tracking group (old domain + new pages) and monitor for drops
- [ ] Crawl old top-linked URLs; confirm 301/308 (not 302/307) redirects
- [ ] Renew old domains indefinitely (and keep redirects in place for at least a year, longer while the old URLs still earn links or traffic)
- [ ] Audit past acquisitions for missed redirects/content — cheap recovered value

## Data points & benchmarks
- M&A is routine at enterprise scale, so migration and consolidation playbooks pay off repeatedly
- Practitioner war stories report fast ranking gains after redirecting an acquired site; those were acquisitions of real businesses. Redirecting an unrelated expired domain to borrow its rankings is a spam-policy violation, and Google may simply ignore or demote it
- Permanent moves need 301/308; 302/307 signal temporary and keep old URLs indexed
- Legacy brand terms keep search volume "for many years" — support them indefinitely

## Mistakes to avoid
- Letting the acquired domain expire — competitors or worse can register it
- Killing content during migration — the #1 avoidable traffic loss with missing redirects
- Using 302/307 redirects for permanent moves
- Ignoring legacy branded search demand
- Forgetting TLS across domains — redirects break with certificate errors
- Never auditing old acquisitions — value is routinely left on the table

## Key principles
- A genuine acquisition inherits earned links and brand equity that can be consolidated into stronger pages (this is a side effect of buying a real business, not a link-buying tactic)
- "More listings vs. one stronger listing" is the core merge decision
- Support old brand names for years — that traffic is free and converting
- Post-mortem audits of past acquisitions are among the cheapest wins in enterprise SEO

## ARTICLE seo-forecasting-model

### SEO Forecasting Model: Traffic → Conversions → Revenue (Spreadsheet Method)

- **Updated**: 2026-10-05

## TL;DR
Executives fund forecasts with ranges and assumptions, not single numbers. Model each keyword cluster: **search volume (or traffic potential) × expected CTR at target position × ramp-up curve × conversion rate × value per conversion**. Build three scenarios (conservative, expected, aggressive), subtract the traffic you already get (forecast the *incremental* gain), and show the gap between the target and what current resources can deliver. That gap becomes the budget ask.

## Framework / Step-by-step
1. **Baseline.** Export 12–24 months of organic clicks, conversions and revenue. Split them into brand and non-brand, and note seasonality. If you need a trend, fit a simple seasonal trend in a spreadsheet, or use a time-series library in a notebook.
2. **Opportunity set.** List target clusters (from the keyword map) with: volume or traffic potential, current position (or "not ranking"), target position, difficulty and page status (exists or new).
3. **CTR curve.** Use your own Search Console CTR by position for non-brand queries, which is more accurate than published curves. Adjust it down for SERPs with AI Overviews, ads or heavy SERP features.
4. **Ramp-up.** Apply a time-to-rank curve:
   - New pages on an established site: about 0% → 100% of target over 6–12 months.
   - Refreshed pages that already rank: about 2–4 months.
   - Lower-authority sites: slower.
5. **Incremental traffic** = (target-position clicks − current clicks) × ramp % per month.
6. **Value.** Multiply incremental clicks by the organic conversion rate and the value per conversion (AOV, or lead value = close rate × deal value). Also report **traffic value** (clicks × CPC) as the "ad-spend equivalent".
7. **Scenarios.** Conservative = lower target positions, slower ramp, −20% CTR. Expected = base assumptions. Aggressive = top-3 positions and faster ramp. Show all three.
8. **Gap and ask.** Compare the expected scenario with the business target. Translate the shortfall into resources (pages, links, dev tickets, headcount) using your historical output-to-result ratios.
9. **Track and re-forecast.** Each quarter, plot actuals against the three lines. Explain variance (updates, seasonality, execution slippage) and update the assumptions.

10. **Add the cost side and ROI.** Cost = content + links/PR + dev hours + tools + people for the forecast period. Report **ROI** = (incremental gross profit − cost) ÷ cost, and **payback month** = first month cumulative incremental profit exceeds cumulative cost. Use gross profit (revenue × margin), not revenue.
11. **Worked example (illustrative numbers):**

| Scenario | Incremental clicks / month at month 12 | Conv. rate | Value per conversion | 12-month incremental gross profit (40% margin) | 12-month cost | ROI | Payback |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Conservative | 6,000 | 1.5% | 3,000 BDT | ≈ 0.70M BDT | 1.2M BDT | ≈ −42% | not within 24 months |
| Expected | 10,000 | 2.0% | 3,000 BDT | ≈ 1.56M BDT | 1.2M BDT | ≈ +30% | month 9 (break-even) |
| Aggressive | 15,000 | 2.5% | 3,000 BDT | ≈ 2.92M BDT | 1.2M BDT | ≈ +144% | month 5 |

Assumptions: clicks ramp linearly from 0 to the month-12 level; cost is 100,000 BDT/month; payback counts cumulative profit vs cumulative cost (costs continue after month 12). A forecast where the conservative case doesn't pay back is normal; it tells executives what must go right. Add a sensitivity line: "every ±0.5 pp in conversion rate moves expected-case profit by about ±25%".

## Actionable checklist
- [ ] Separate brand and non-brand; forecast non-brand growth only
- [ ] Use your own CTR-by-position data where possible
- [ ] Discount CTR for AI Overviews and SERP features
- [ ] Apply ramp-up curves by page type (new vs refresh)
- [ ] Forecast incremental gain, not total traffic
- [ ] Present 3 scenarios with an explicit assumptions table
- [ ] Tie traffic to revenue or pipeline, and show traffic value as a secondary metric
- [ ] Show the target-vs-forecast gap and the resources needed to close it
- [ ] Show cost, ROI and payback month per scenario
- [ ] Re-forecast quarterly against actuals

## Data points & benchmarks
- Clicks to the #1 organic result fall noticeably when an AI Overview is present, so discount any CTR curve built before AI Overviews were common.
- On average, one top-ranking page ranks for about 1,000 keywords, which is why traffic potential beats single-keyword volume for forecasts.
- Many SEO projects take 3–6+ months to show results. A forecast with a flat first quarter is realistic, not pessimistic.

## Mistakes to avoid
- Single-point forecasts ("we'll get 100k visits") with no ranges or assumptions
- Using total search volume × #1 CTR for every keyword (wildly optimistic)
- Counting brand traffic growth as an SEO result
- Ignoring cannibalization: two pages don't both get the #1 CTR
- Never comparing forecasts with actuals, which loses credibility next budget cycle

## Key principles
- Executives want one number (revenue); give it with a range.
- The forecast is a negotiation tool. The gap to target justifies resources.
- Assumptions should be visible and editable. Transparency earns trust.

## ARTICLE seo-forecasting

### SEO Forecasting: The Art Of Getting Buy-In

- **Updated**: 2026-10-05

## TL;DR
Forecasts turn SEO into a budget conversation: project your traffic/traffic-value trajectory (with uncertainty bands), compare against company targets or competitors, and use the gap to argue for resources — or a lower target. Time-series forecasting scripts (e.g., a Python notebook with an open-source forecasting library) can turn traffic exports into 1-year forecasts in minutes, no data scientist needed, but treat the output as a scenario, not a promise.

## Framework / Step-by-step
1. **Why forecast**: enterprise = annual/semi-annual projections vs. company goals. If you project +15% YoY at current resources but the target is +25%, that gap justifies more budget (content, links, internal linking) — or a renegotiated target. Agencies: forecasts elevate pitches and justify budgets.
2. **Keyword-level forecasts**: search volume × CTR is the classic formula, but flawed (one keyword per page; generic CTR curves). Fixes: custom CTR curves from your own Search Console data, forecast keyword volume itself (a keyword research tool), or use "traffic potential" (total traffic to the #1 page across all its keywords).
3. **First vs. third-party data**: analytics/Search Console = most accurate for your own site (seasonality, granularity). Third-party SEO data = the only way to forecast vs. competitors; its traffic figures are modeled estimates, so treat them as directional.
4. **Run a time-series forecast** (Python notebook + open-source forecasting library, or spreadsheet trend lines):
   - Export a CSV of historical organic traffic (or estimated traffic value) from your SEO tool, or from Search Console/analytics for your own site
   - Load the CSV into a hosted notebook, run all cells, and read the chart
   - Variants: single-site traffic, single-site traffic value, 2–5 site competitor traffic, 2–5 site competitor traffic value, 2–5 page-level competitor traffic
5. **Interpret**: 80% probability the result lands in the shaded band. If a competitor overtakes you at current effort levels → case for strategy change or more resources; if you're pulling away on a page → deprioritize updating it; if a competitor is closing in → refresh/expand.
6. **Tune the scripts**: add core-update dates (YYYY-MM-DD list) as event/holiday regressors, adjust the event window (e.g., 14 days after each update), change the horizon (e.g., 365 days → 1095 for 3 years), change the input date range, filter to a site section or page, recolor lines for brand.

## Actionable checklist
- [ ] Export your domain's organic traffic (and, if available, traffic value) history from Search Console/analytics or an SEO tool
- [ ] Run the single-site scripts; note the 1-year projection and uncertainty band
- [ ] Repeat for 2–4 key competitors; chart overtake/crossover points
- [ ] Compare projected growth vs. company target; document the resource gap
- [ ] Run page-level forecasts for your most valuable pages vs. their direct competitors
- [ ] Update forecasts after major strategy changes or core updates
- [ ] Add new core update dates to the script's event list as they happen

## Data points & benchmarks
- Forecast bands = 80% probability range
- Common script settings: 14-day post-update window, 365-day horizon
- One worked example: a site projected to grow 880K → 1.3M monthly visits (+~48%) and $1.9M → $2.9M estimated traffic value (+~53%) over one year
- One reported case: a model predicted a ~50% traffic loss over a year for a large health publisher and tracked subsequent core-update declines reasonably well about 2 months ahead (a single case, not a guarantee)
- Forecasts of both branded + non-branded combined — split if it matters for your case

## Mistakes to avoid
- Volume × generic CTR as the whole forecast — pages rank for many keywords
- Building overly complex forecasts — "the ROI of building complex forecasts is not there"
- Treating a forecast as a promise — refresh periodically; strategy changes invalidate trends
- Forecasting only yourself — competitor trajectories are the actual budget lever

## Key principles
- A forecast's job is to reveal gaps: projected vs. target, you vs. competitor — gaps are what unlock resources
- Uncertainty bands make forecasts honest (80% interval)
- Page-level forecasts are a content-refresh prioritization tool, not just a budget tool
- Forecasts take minutes with the scripts; the bottleneck is acting on them

# Traffic Drop Doctor

You are a senior SEO diagnostician. Your job is to turn "our traffic dropped" into a **ranked, evidence-backed diagnosis and a recovery plan**, in under an hour, as a report the user can hand to a client or boss.

The core idea: **clicks = impressions × CTR**. Every drop is fewer impressions (ranking loss, indexing loss, lower demand), a lower CTR (SERP features, AI Overviews, worse titles), or both. Find out which, where (which pages, sections, queries, devices) and when (which date, and what happened then). That narrows a dozen possible causes down to the one or two that matter.

## Step 1: Intake (ask, but don't block)
Ask the questions below in one message. If the user can't answer, continue and note the gaps in the report.
1. **Site and drop:** the URL, roughly when the drop started, and how big it is (% or clicks per day). Did they see it in Search Console, analytics or both?
2. **Changes:** any deploy, redesign, migration, CMS or plugin update, URL change, content pruning or new template in the last 3 months? Get dates.
3. **Scope:** is the whole site affected, or one section or page type?
4. **Business context:** is the business seasonal? Any marketing, PR or brand changes?
5. **Data access:** can they export from Google Search Console? (If not, give them [references/how-to-export-gsc.md](references/how-to-export-gsc.md).)

Adapt to the user's level:
- **Beginner (business owner):** explain in plain language, use no unexplained jargon, give the 3 most important actions, and reassure them without promising.
- **Agency or freelancer:** produce the full client report.
- **Advanced:** include the method, segment tables and edge cases.

## Step 2: Get the data
Best input, explained in [references/how-to-export-gsc.md](references/how-to-export-gsc.md):
- **A Search Console Compare export** (Performance → Date → Compare, e.g. last 28 days vs the previous 28 days, or the same period last year). The .zip contains Queries, Pages, Devices and Countries.
- **A daily Dates.csv covering 16 months** (a non-compare export) for the timeline, drop date and year-over-year comparison.
- **Optional `events.csv`:** Google updates plus the site's own deploys and migrations. Start from [references/google-updates.csv](references/google-updates.csv) (Google updates through September 2026, taken from the Google Search Status Dashboard). Add newer updates from the dashboard and the site's own deploys. The script warns when the file looks out of date.

## Step 3: Analyze
**If you can run Python:**
```bash
python scripts/analyze_gsc.py --export <compare.zip or folder> --dates <Dates.csv> \
  --brand "brandname,brand name" --events <events.csv> --site "example.com" --out report
```
`--out` is a **folder**. It contains `report.md` (a draft report), `findings.json` (all metrics for you), CSVs of losing queries, pages and sections, and `timeline.png`. Read `findings.json`, the ranked hypotheses and any **Data warnings** (stale data, truncated exports, unreadable events), then **check them against the intake answers**. The script can't see deploys you weren't told about, manual actions, or what the SERP looks like now.

**If you can't run code** (chat-only agents or spreadsheet users), follow the manual method in [references/diagnosis-guide.md](references/diagnosis-guide.md#manual-spreadsheet-method). It uses the same six calculations, done with spreadsheet formulas.

## Step 4: Diagnose
Use the **signature table** in [references/diagnosis-guide.md](references/diagnosis-guide.md). Each root cause has a distinct fingerprint:

| What the data shows | Most likely cause |
|---|---|
| Zero clicks and zero impressions on some days | Tracking, verification or sitewide deindexing |
| One section's impressions collapse while its position holds | Indexing or technical problem in that template |
| Sudden step-down on an update date, with position losses on many pages | Algorithm update |
| Sudden drop within days of a deploy or migration | Self-inflicted technical change |
| Position held, CTR fell, mostly on informational queries | AI Overviews or SERP features |
| Gradual position loss on specific pages | Competitors or content decay |
| Impressions fell at stable position, and the same thing happened last year | Seasonality or demand |
| Branded clicks fell | Brand demand (not an SEO problem) |

Rules:
- **Several causes often stack up.** The demo example has three. Quantify each one's share of lost clicks, and separate out seasonality first: the script reports the year-over-year change and a seasonally adjusted drop.
- **For migrations and restructures, pair old URLs with new ones.** The script matches them by slug and lists old URLs with no new equivalent (`findings.json` → `migration.unmatched_urls`). Those URLs are where the loss is fixable.
- **Use fresh data.** If the export ends more than about 10 days ago, ask for a new one before sending a report.
- **Demand exact date alignment.** An update that "roughly" matches is not proof.
- **Always tell the user to check manual actions**, because performance data can't show them.
- **Never recommend changes during an active algorithm rollout.**

## Step 5: Recovery plan
Take the fixes, timelines and "what to expect" for each confirmed cause from [references/recovery-playbooks.md](references/recovery-playbooks.md). Order them by **impact ÷ effort**. Self-inflicted technical issues come first: they're cheap and usually recover within weeks.

2. What happened
3. Causes ranked, each with confidence and evidence
4. What we can't recover
5. Action plan

7. Appendix

Write in the user's language: if they write in Bangla or Banglish, write the report and your reply in Bangla (simple for beginners, professional for agencies and experts) and keep SEO terms in English. For a beginner, also give a 5-line plain-language version in your reply.

## Guardrails
- Diagnoses are probabilistic. State the confidence and how to confirm each cause, and never present a guess as fact.
- Don't promise recovery or timelines. Give typical ranges from the playbooks, with conditions.
- Separate the controllable (technical fixes, content) from the uncontrollable (AI Overviews, demand). Clients trust reports that admit what can't be fixed.
- Recommend white-hat fixes only. Never suggest disavowing links unless there is a manual action for unnatural links.
- The demo data in `examples/` is fictional. Don't cite its numbers as real benchmarks.

## REFERENCE diagnosis-guide

### Diagnosis Guide: Cause Signatures, Confirmation Checks, Manual Method

## Contents
- The 6 analyses
- Cause signature table
- How to confirm each cause
- Order of elimination
- Manual spreadsheet method (no code)
- Common traps

## The 6 analyses
1. **Totals and decomposition.** Compare clicks, impressions, CTR and position for before vs after. Then split the click change:
   - impressions effect = (Impr_after − Impr_before) × CTR_before
   - CTR effect = (CTR_after − CTR_before) × Impr_after

   The bigger effect tells you whether this is mainly a visibility problem or a click-through problem.
2. **Timeline.** Find the drop date (the biggest 14-day before/after change in daily clicks). Note its shape: a sudden step-down means an event; a gradual slope means decay, competition or demand. Compare the same weeks last year (seasonality). Check whether it has partly recovered.
3. **Query patterns.** Label each losing query:
   - **ranking_loss**: position worsened by 3 or more (or by 1.5 or more inside the top 10)
   - **ctr_loss**: position within ±1.5, CTR down 25% or more, impressions not collapsing
   - **demand_loss**: impressions down 30% or more at a stable position
   - **disappeared**: impressions fell to 0

   Then sum the lost clicks per label.
4. **Sections.** Group pages by their first URL folder. A cause that hits one template or section is almost always technical or content-specific to that section.
5. **Segments.** Brand vs non-brand, informational vs other queries (CTR at a stable position), device, and country.
6. **Event match.** Check the drop date against Google updates and the site's own changes (±7 days, allowing for indexing lag).

## Cause signature table
| Cause | Timeline | Impressions | CTR | Position | Scope | Tell-tale sign |
|---|---|---|---|---|---|---|
| Tracking or data glitch | Cliff to ~0 | ~0 | n/a | n/a | All | Zero days; analytics disagrees with Search Console |
| Sitewide deindexing (noindex, robots.txt, auth wall) | Cliff over days | ↓↓ | ~ | Stable for remaining URLs | All | "Excluded by noindex" or "Blocked by robots.txt" surge in the Pages report |
| Section indexing or technical problem | Step | ↓↓ in one section | ~ | **Stable** | One folder or template | Pages at zero impressions; deploy date nearby |
| Migration or redirect error | Step after launch | ↓ | ~ | ↓ | Old URLs | Old URLs 404 or redirect-chain; new URLs not indexed yet |
| Core or algorithm update | Step on update dates | ↓ | ↓ (follows position) | **↓ on many pages** | Sitewide or a content type | Exact date match; competitors gained |
| Spam update or manual action | Step | ↓↓ | n/a | ↓↓ | Sitewide or a section | Manual action notice; link-scheme or scaled content history |
| AI Overviews or SERP features | Gradual or step as features roll out | ~ or ↑ | **↓↓** | **Stable** | Informational queries | CTR loss at stable position, informational > other |
| Competitors or content decay | Gradual | ↓ | ↓ | Gradual ↓ | Specific pages | Fresher or better pages now outrank you |
| Seasonality or demand | Cyclical | ↓ | ~ | Stable | All or a topic | Same pattern in the same weeks last year |
| Brand demand | Gradual | ↓ brand | ~ | Stable | Brand queries | Branded impressions fall |
| Intent shift | Step | ↓ for specific queries | ↓ | ↓ | A few big queries | The SERP now shows a different content type |

(↓ = down, ↓↓ = sharply down, ~ = roughly unchanged)

## How to confirm each cause
- **Tracking:** compare with analytics. Check the Search Console property type (domain vs URL-prefix) and the verification status.
- **Indexing:** URL-inspect 3–5 affected URLs ("URL is not on Google"?). Check the Pages report reasons, view the page source for `noindex`, check robots.txt and canonical tags, and look at the HTTP status.
- **Migration:** crawl the old URL list and expect 301 → 200. Look for chains, loops and 404s.
- **Algorithm update:** look up the official rollout dates on the Google Search Status Dashboard. Compare the drop date at daily granularity. Search the top losing queries and see who gained.
- **Manual action:** Search Console → Security & Manual Actions.
- **AI Overviews or SERP features:** search the top CTR-loss queries in an incognito window from the right country and note any AI Overview, video, PAA, shopping, forum or other features. A rank tracker with SERP-feature history is faster.
- **Competitors:** for each of the top 10 losing queries, record who now ranks above you, and compare freshness, depth, format and links.
- **Seasonality:** compare year over year in Search Console, and check the topic's Google Trends curve.
- **Brand:** branded impressions trend vs brand activity (PR, ads, reputation).

## Order of elimination
Check the cheapest things first:
1. Tracking
2. Manual actions
3. Indexing and technical
4. Your own changes
5. Algorithm updates
6. SERP or CTR changes
7. Competitors and content
8. Seasonality and demand
9. Brand

## Manual spreadsheet method
Use this if you can't run the script. It needs the Compare export opened in any spreadsheet.
1. **Pages sheet.** Add these columns:
   - `ΔClicks = after − before`
   - `ΔPos = after − before` (positive means worse)
   - `ΔImpr% = after/before − 1`
   - `Section`: the first folder of the URL, e.g. `=REGEXEXTRACT(A2,"https?://[^/]+(/[^/]+/)")`
2. **Pivot by Section.** Sum the clicks and impressions for each period, and average the position weighted by impressions. Sort by ΔClicks. Look for:
   - a section with impressions down 60% or more and a stable position (indexing)
   - position up 2 or more (ranking loss)
3. **Queries sheet.** Add `CTR_b = clicks/impr` and `CTR_a`, then label each row with a formula:
   - `=IF(ΔClicks>=0,"ok",IF(impr_after=0,"disappeared",IF(ΔPos>=3,"ranking",IF(AND(ABS(ΔPos)<1.5,CTR_a<0.75*CTR_b),"ctr",IF(ΔImpr%<=-0.3,"demand","mixed")))))`
   - Pivot the sum of ΔClicks by label to get the share of loss per pattern.
4. **Brand split:** filter the queries that contain the brand name and compare the totals.
5. **Informational CTR:** filter queries starting with how, what, why or similar (or containing "?") that have a stable position, and compare their CTR change with the other queries.
6. **Timeline:** chart `Dates.csv` with a 7-day average. Mark update dates and deploys, and compare the same weeks last year.
7. **Migration pairing** (if URLs changed): put old and new URLs side by side and match them by slug (the last path part). For each old URL, check that it 301s to its pair. Old URLs with no pair and lost clicks are where the fix pays off.
8. **Seasonality adjustment:** seasonal share ≈ last year's % change ÷ this year's % change over the same 28-day windows. Remove that before splitting the rest between the other causes.

## Common traps
- Using queries for totals: anonymized queries are missing, so use pages or the overall chart.
- Average position rising (getting worse) because you *gained* new low-ranking impressions. Check impressions before you call it a ranking loss.
- Comparing weeks that contain different holidays, or different numbers of weekend days.
- Blaming an update that started 3 weeks before the drop.
- Reading a drop in a single page's clicks as sitewide.
- Ignoring that two causes can overlap. Quantify each one.
- Reading a migration as an indexing failure: a section that drops to zero is often just moving to new URLs. Check whether another section gained at the same time.
- Using an export that's weeks old. Always check the last date in the data.

## REFERENCE how-to-export-gsc

### How to Export Search Console Data for a Traffic-Drop Diagnosis

The export takes about 5 minutes and needs no technical skills. You need access to the site's Google Search Console property (owner, full or restricted user).

## Export 1: the Compare export (required)
1. Open Search Console → choose the property → **Performance → Search results**.
2. Make sure **Total clicks**, **Total impressions**, **Average CTR** and **Average position** are all switched on. The export includes only the metrics you have selected.
3. Click the **Date** filter → **Compare** tab, and pick one of:
   - **"Compare last 28 days to previous period"** for a recent drop.
   - **A custom range:** 4 weeks after the drop vs 4 weeks before it. This is best if you know the date.
   - **Year over year** (the same 28 days last year), if the business is seasonal.
4. Click **Export → Download CSV**. You get a .zip containing `Queries.csv`, `Pages.csv`, `Countries.csv`, `Devices.csv` and others. **Keep the .zip as it is.**

## Export 2: the daily timeline (strongly recommended)
1. Change the Date filter to **Filter → Last 16 months** (not Compare).
2. **Export → Download CSV**. From this .zip you only need `Dates.csv`.

## Optional: an events file
Create a simple CSV called `events.csv` with these columns:
```
name,type,start,end
March 2025 core update,core,2025-03-13,2025-03-27
Site redesign launch,deploy,2025-04-02,2025-04-02
```
- Use type `core`, `spam` or `algorithm` for Google updates.
- Use type `deploy`, `migration`, `redesign` or `content` for your own changes.
- Start from `google-updates.csv` in this folder. Check the **Google Search Status Dashboard** for updates newer than the file, and add them.

## Good to know
- Search Console hides rare ("anonymized") queries, so query totals are lower than page totals. The analyzer uses page totals for the headline numbers.
- The data is usually about 2 days behind.
- For very large sites, the export is capped at 1,000 rows per table. Analyze one section at a time with a **Page** filter, or use the Search Console API or bulk export.
- If you can't export, screenshots of the Performance graph (16 months) and the Queries and Pages tables (Compare mode, sorted by click difference) still allow a rough diagnosis.

## REFERENCE recovery-playbooks

### Recovery Playbooks by Cause

Each playbook gives the fix, then **what to expect**. Typical ranges assume the fix is complete. They are not guarantees, so say that in the report.

## Contents
- Tracking or data glitch
- Sitewide or section indexing problem
- Migration or redirect error
- Core or algorithm update
- Spam update or manual action
- AI Overviews or SERP features (CTR loss)
- Competitors or content decay
- Seasonality or demand
- Brand demand
- Intent shift

## Tracking or data glitch
- **Fix:** restore the tracking tag or Search Console verification. Make sure you're looking at the right property (domain vs URL-prefix, http vs https, www).
- **Expect:** the data is corrected going forward; the past gap can't be refilled. Annotate it in your reports.

## Sitewide or section indexing problem
- **Fix:**
  - Remove the accidental `noindex` or `X-Robots-Tag`, or the robots.txt disallow.
  - Fix canonicals that point elsewhere.
  - Restore 200 status codes, or 301 removed URLs to their equivalents.
  - Resubmit the sitemap, and request indexing for the 10–20 most important URLs.
  - Add a deploy checklist (noindex and robots.txt checks) to stop it happening again.
- **Expect:** often the fastest recovery. Important pages are usually re-indexed within days to a few weeks; long-tail pages take longer.

## Migration or redirect error
- **Fix:**
  - Map every old URL to its closest new equivalent with a single-hop 301.
  - Repair chains and loops.
  - Update internal links and canonicals to the final URLs.
  - Resubmit the sitemaps, and keep redirects for at least a year.
- **Expect:** most traffic returns over weeks to a few months once the redirects are correct. Lost link equity from URLs left at 404 needs the redirects to be added.

## Core or algorithm update
- **Fix:**
  - Don't change anything mid-rollout.
  - Afterwards, audit the top losing pages against Google's helpful-content self-assessment: original information, depth, expertise and first-hand experience, satisfying the intent, and trust signals (author, sources, about page).
  - Improve or merge thin pages; remove unhelpful scaled content.
  - Compare against the pages that gained.
- **Expect:** recovery, if it comes, often shows at the *next* core update after the improvements (months). Some sites never fully recover. Be honest about that.

## Spam update or manual action
- **Fix:**
  - **Manual action:** fix exactly what the notice says (unnatural links: remove them, or disavow what you can't remove; thin or scaled content: remove or improve it), then file a reconsideration request.
  - **Algorithmic spam:** stop the tactic and clean up.
- **Expect:** a reconsideration review takes days to weeks. With an algorithmic hit, ignored links simply stop counting, so recovery comes from new legitimate signals.

## AI Overviews or SERP features (CTR loss)
- **Fix:**
  - Rewrite titles and metas for clearer value: specifics, freshness, proof.
  - Add answer-first sections that AI can cite (that earns brand visibility even without the click).
  - Add schema that still earns rich results.
  - Add original data, tools and templates, which AI summaries can't replace.
  - Shift the content mix toward commercial, comparison and experience-led queries.
  - Track AI citations and AI referral traffic.
- **Expect:** **part of this loss is structural and won't come back.** Report it as a market change. Measure success by CTR at a stable position, AI citations, and conversions per visit.

## Competitors or content decay
- **Fix:**
  - Refresh the top 10–20 losing pages: match the current intent and format of the winners, add missing subtopics, update facts and dates, and improve the media.
  - Strengthen internal links to these pages and earn a few relevant links.
  - Consolidate pages that cannibalize each other.
- **Expect:** refreshed pages often move within weeks to 3 months. Track the target queries weekly.

## Seasonality or demand
- **Fix:** no SEO fix is needed. Re-baseline on year-over-year comparisons, and prepare seasonal content 6–8 weeks before the peak. If the market shrank, expand into adjacent topics.
- **Expect:** traffic follows the demand curve.

## Brand demand
- **Fix:** escalate to marketing. Check brand campaigns, PR, reviews and reputation, and competitor bidding on your brand. Protect your branded results (sitelinks, Business Profile, review sites).
- **Expect:** depends on brand activity, not SEO.

## Intent shift
- **Fix:** look at what the SERP rewards now (format, angle, freshness). Rebuild the page to match it, or target a related query that still matches your page.
- **Expect:** weeks to months after the rebuild. Some intent shifts reverse on their own (news-driven ones, for example).
